# CEREBRO — 2026-09-26

## Model routing and Jev

- [Introducing typesafe/jev-router](https://x.com/OpenRouter/status/2103610898690855161): OpenRouter's cache-aware router picks the model and reasoning effort per request to balance quality, speed and cost, and the cache awareness is what makes it worth watching.
- [Theo on mid-task routing](https://x.com/theo/status/2103614897129144545): switching to a "dumber" model halfway through a task saves little because cache writes are such a large share of cost, which is a caveat for any router.
- [Theo benching the router](https://x.com/theo/status/2103701465084919906): early numbers say it is basically a DeepSeek 4.1 flash router, so treat the quality-balancing claim as unproven until the full benchmark lands.
- [Theo: "Jev is incredible"](https://x.com/theo/status/2101857305570721847): he worries people are using Jev wrong and has a video on the intended usage.
- [A single function Jev-like wrapper for LLMs](http://allanrbo.blogspot.com/2026/09/a-jev-like-wrapper-for-llms-including.html): reads the model's token probabilities (logprobs) to get typed, calibrated answers to a prompt, a cheap way to turn any logprob-exposing model into a classifier (a commenter says Fireworks AI has better grammar support).
- [Ollaya](https://ollaya.dev/): Ollama-style local runner for Jev-style decision models that return typed answers with probabilities in milliseconds, for example gating an agent's `git push --force` before it runs.

## Model cost and quality

- [I priced 203 PRs from my Claude Code agents](https://www.reddit.com/r/ClaudeAI/comments/1wqis66/i_priced_203_prs_from_my_claude_code_agents_opus/): Opus 5.5 cost about half of Sonnet 5 per line of code across the author's real agent PRs, which challenges "cheaper tier means cheaper output".
- [bcherny: HAProxy C to Rust port](https://x.com/bcherny/status/2102439069053747549): Opus 5.5 and Fable 5.1 both passed nearly all of HAProxy's tests, but Opus 5.5 finished in 9.5 hours versus 12 and cost 51% less.
- [Theo's guide to maximizing success with Opus 5.5](https://x.com/theo/status/2103276852618068458): a practitioner write-up, with credit to Addy Osmani, on getting the most out of the current daily-driver model.
- [Ternary Bonsai 2 27B](https://x.com/itsjdraven/status/2103678685362761962): a 27B model at 1.76-bit ternary weights in about 5.9 GB, with 262K context, text and image input, Apache 2.0 licence, and a claimed 98.2% of benchmark performance, so agentic-capable local inference gets much cheaper if it holds up.

## Claude Code

- [Claude Code v2.1.283](https://github.com/anthropics/claude-code/releases/tag/v2.1.283): adds an `x-claude-code-prompt-id` gateway hint header (opt in with `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`) so LLM gateways can group the requests behind one user prompt, and an `availableModelsMatch` managed setting for exact model pinning.
- [bcherny on making Claude Code and Desktop faster](https://x.com/bcherny/status/2102854267782705648): a blog post with techniques from the recent speedups that apply to any app you want to speed up.

## Skills and plugins

- [Claude plugin submission portal](https://x.com/ClaudeDevs/status/2103577007938228300): a new portal to submit a plugin, track its review and see usage, with plugins (MCP plus skills) positioned as the way to build for Claude and MCP usage across Claude products up 110x this year.
- [anthropics/claude-plugins-official](https://github.com/anthropics/claude-plugins-official): Anthropic's curated directory of Claude Code plugins, with a reminder that Anthropic does not control or verify what a plugin's MCP servers and files contain.
- [anthropics/skills](https://github.com/anthropics/skills): Anthropic's reference Agent Skills repository, the canonical examples of folders of instructions, scripts and resources that Claude loads on demand.
- [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill): a multi-phase security audit skill (recon, hunting, candidate validation, independent verification, reporting) that seeded Cloudflare's vulnerability discovery harness and is a good template for isolated-agent pipelines.

## Agent workflow

- [Theo on remote agent setups](https://x.com/theo/status/2103710437951131865): put Ubuntu on a spare machine, ssh in, run `npx t3 connect`, and do all agent work remotely.
- [Theo: how most devs should work](https://x.com/theo/status/2103711913771470901): he prefers this remote setup to cloud agents and says macOS is bad at running many agents in parallel.
- [Theo: your Mac is slowing you down](https://x.com/theo/status/2090528543746965991): he reports much better agent performance on Linux, especially on the file system side.
- [RT @daradoescode on T3 Code](https://x.com/theo/status/2103584511116390716): a user complains T3 Code was "silently nerfed", limits now run out faster, and an orchestrator v2 is coming, which is a reminder that limits are part of tool quality.
- [Simon Willison, 24 Sep 2026](https://simonwillison.net/2026/Sep/24/harder/): coding agents make software engineering harder, because getting their full potential takes extraordinary discipline and knowledge.

## Agent harnesses and orchestration

- [paperclipai/paperclip](https://github.com/paperclipai/paperclip): open-source Node.js and React orchestration for a team of AI agents, where you bring your own agents, assign goals, and track work and costs from one dashboard.
- [androoAGI/starnet](https://github.com/androoAGI/starnet): local-first desktop harness where bring-your-own-key agents run as a pixel-art space station that projects live runtime state.
