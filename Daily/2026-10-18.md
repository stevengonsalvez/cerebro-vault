## Coding agents

- [anomalyco/opencode](https://github.com/anomalyco/opencode): open-source terminal coding agent, installable via curl, npm, or scoop; the main OSS alternative to Claude Code and Codex, and many tools in this batch target it.
- [anthropics/claude-code](https://github.com/anthropics/claude-code): the reference terminal agent; the README now marks npm install as deprecated in favour of native installers, so update install scripts and docs.
- [anakitaonrails/ai-memory](https://github.com/akitaonrails/ai-memory): shared long-term memory that lets you quit Claude Code mid-task and resume in Codex in the same directory without re-explaining; it targets vendor lock-in at the context layer.
- [No pull requests, no code review. We push to main.](https://x.com/thorstenball/status/2110035978685747457): Thorsten Ball describes agents that read production logs, watch deploys, grant feature flags, and verify their own work end to end; the guardrails are the interesting part.
- [Sphinx](https://sphinx-six-theta.vercel.app/): Git hook that quizzes you on your agent's code before it ships, using minimal tokens via your existing agent or any OpenAI-compatible endpoint; HN skeptics say the people who'd benefit will click through anyway.

## LLM mechanics

## Orchestration and multi-agent

- [stablyai/orca](https://github.com/stablyai/orca): runs Codex, Claude Code, OpenCode, or Pi side by side, each in its own git worktree, with mobile notifications and follow-ups; worktree-per-agent is becoming the standard isolation pattern.
- [mattpocock/sandcastle](https://github.com/mattpocock/sandcastle): TypeScript `sandcastle.run()` runs agents in Docker, Podman, or Vercel sandboxes with a branch strategy and merges commits back; this is programmable sandboxed orchestration.
- [Orchestrator-V2 in T3 Code](https://x.com/theo/status/2111547081735496018): a user reports Claude driving Grok CLI and Devin-hosted Gemini as subagents; cross-vendor subagents are showing up in mainstream tooling.
