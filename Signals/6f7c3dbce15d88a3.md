> Codebase structure improves agent-written test quality; practical tip

pro tip: structure the codebase before you ask your agents to write tests.

This one "step" has improved the quality of tests more than any prompt tweak I have tried. When files and directories follow a clear convention, the model knows where each piece of logic lives, what its dependencies are, and what a test for it should look like.

This way, it can write focused tests for each layer, mock the right boundaries (if relevant), and cover more branches in the first go.

If you let it go loose and just say "write tests", it only sees whatever code you point it at. It tends to cover the obvious
